Arivu is powered by a deterministic, graph-based execution engine built on top of `LangGraph`. This design ensures that agentic steps are distinct, auditable, and can be easily intercepted for debugging or human-in-the-loop approvals.

## The Execution Graph

Every time `app.run_pipeline()` is invoked, the input query passes through a highly structured state machine. The edges of this graph are defined natively in `arivu.pipeline.edges`.

<Steps>
  <Step title="Query Intake & SQL Generator">
    The pipeline ingests the user's natural language string and contextualizes it against the localized database schema memory. It attempts to generate valid SQL tailored explicitly to the active dialect (PostgreSQL, MySQL, or SQLite).
  </Step>

  <Step title="Query Verifier">
    Before execution, the raw SQL is passed to a syntax verifier. If the SQL is invalid, it is routed *back* to the `SQL Generator` equipped with the database's specific error message to self-correct up to a predefined retry threshold.
  </Step>

  <Step title="Admin Approval Gate">
    If the engine operates in `Mode: admin` and detects destructive DML operations (e.g., `DROP`, `DELETE`, `UPDATE`), the graph halts. It awaits explicit human validation via the `admin_approval` node. If rejected, the execution terminates at the `error_boundary`.
  </Step>

  <Step title="Database Execution & Retrieval">
    Approved (or read-only) SQL is natively executed against the active connection cluster. If the payload returns massive datasets (e.g., thousands of rows), the `result_embedder` chunks the returned telemetry and stores it via FAISS (Facebook AI Similarity Search) within the active session.
  </Step>

  <Step title="Response Generation & Memory Logging">
    The `retrieval_agent` fetches only the most semantically relevant rows to answer the user's prompt, preventing context-window overflows. The LLM synthesizes a final conversational response. All steps are logged permanently into the memory layer via the `memory_write` node.
  </Step>
</Steps>

## Observability

Because each distinct node returns specific metadata, the Arivu Engine guarantees complete observability payload outputs. You can visually inspect how many retries a query required and the latency of individual components using the [Arivu Dashboard](/dashboard/overview).
