The Arivu framework inherently understands that complex database interactions require multi-turn context. When you initialize your orchestrator, you can deploy a scalable memory state layer to persist conversation histories, SQL schema analyses, and execution tracking across sessions.

## Storing History 

By default, any queries routed through `app.query()` with an identical initialization footprint will utilize the built-in memory store. This prevents the LLM from executing redundant table extractions on subsequent prompts.

```python
from arivu import Arivu

db_app = Arivu.connect(
    database_url="postgresql://user:pass@localhost:5432/main",
    llm_provider="openai"
)

# Call 1: Requires heavy schema lookup.
res1 = db_app.run_pipeline(
    db_app.query("Show me total users.")
)

# Call 2: Infers structure immediately from context cache!
res2 = db_app.run_pipeline(
    db_app.query("Now filter them by the US region only.")
)
```

## Global Configurations

Memory limits and TTL policies can be overridden by configuring your active connections via the [Dashboard Interface](/dashboard/overview) or directly in your underlying key-value initialization settings.
